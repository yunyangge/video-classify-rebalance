# 单份候选池如何重平衡

1. 读取分类表，分离缺少必需信息的记录。用内容、形态、语种、分辨率档位和技术状态分组。
2. 最多五条的小组枚举选与不选。大组按高密度、低密度、质量顺序生成若干完整视频组合，保留空组合、全选组合和可选初始名单。
3. 先用连续松弛估计各组需要多少小时，再围绕这些位置补充组合。最后用整数求解，每组选择一个组合，得到完整视频名单。
4. 从导出的名单重新计算各项指标，核对它确实来自候选池，且原字段未变。

## 目标顺序

| 顺序 | 最小化什么 |
|---|---|
| 1 | 总时长距离目标区间的差值 |
| 2 | 内容、形态、语种的时长不足与超额 |
| 3 | 单条技术指标未达标的视频小时；一条违反两项时分别计数 |
| 4 | 高分辨率小时缺口 |
| 5 | 密度排名的小时加权值，优先较高密度 |
| 6 | 质量排名的小时加权值，像素数高、上传时间新优先 |

后一项保持前一项已取得的结果。设置 100 小时目标、某类目占比 40%—60%，对应的类目目标始终是 40—60 小时。

## 平均密度

总体和每个内容一级、二级及制作形态分别计算 `总字节 ÷ 2^30 ÷ 总小时`，不超过 `max_gib_per_hour`。语言只设置时长比例。

例如两条视频都为 1 小时，大小分别为 3 GiB 和 2 GiB，平均密度就是 2.5 GiB/小时。设置上限 2.5 时可以一起入选。

## 求解预算与结果

`lp_seconds` 是每次连续松弛的预算，`solve_seconds` 是本轮整数求解各优先级共享的预算。大模型在独立进程执行，到时保留已验证可行的名单。大组只搜索生成的有限组合，扩大组合预算或细化轮数会增加搜索范围和运行时间。

`completed` 表示执行完成，`hard_constraints_passed` 表示唯一性、来源原值和平均密度通过。`quota_requirements_passed` 表示时长和比例目标满足，`technical_quality_passed` 表示技术要求满足；两者都为真时 `passed` 才为真。

测试使用生成数据覆盖小组最优选择、高低密度搭配、目标优先级、无有效候选和导出后篡改检查。真实 GPU 编码速度及大规模求解耗时应在部署环境记录。
